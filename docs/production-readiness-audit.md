# Dealroom production-readiness audit

**Reviewed November 25, 2026.** Local synthetic demo is verified. Real creator data, real email delivery, and an independent production handoff should remain gated. The approval and delivery foundations are worth keeping. The release blockers concern commercial correctness, identity, privacy, and recovery.

## Release blockers

| Priority | Finding and evidence | Close when |
| --- | --- | --- |
| P1 | **Identity and real delivery are still sandbox features.** The session endpoint issues an anonymous browser token. The proxy secret authenticates the frontend service. The API accepts simulated inbound text, and the worker delivers by inserting a simulated inbox receipt. The approval binds the body digest and version. The current delivery model has no provider, recipient, or confirmed mailbox identity to bind. [Session and inbound commands](../backend/app/api.py#L160) · [Delivery handler](../backend/app/storage.py#L556) | Creator accounts, workspace membership and approval attribution exist. Real mail enters through an authenticated ingestion boundary. An approval binds recipient, subject and exact body. Provider receipts, ambiguous outcomes and recipient changes have explicit tests. |
| P1 | **The profile editor can overwrite a newer policy.** It captures the fields when editing starts, then the parent passes its current policy version on save. A delivery-triggered profile refresh can advance that version while keeping old form fields, letting the stale form pass the backend check. [Editor](../frontend/components/creator-profile.tsx#L8) · [Profile refresh](../frontend/app/page.tsx#L64) · [Save](../frontend/app/page.tsx#L111) | Each editor holds the base version with its form data. A two-tab regression proves that an intervening update gets a conflict and offers a safe reload or merge path. |
| P1 | **A draft can omit a binding term.** The renderer uses the amount of the exclusivity surcharge to decide whether to say exclusivity is included. I confirmed that a USD 2,400 offer for a reel with 30 days of exclusivity yields an acceptance draft with no mention of exclusivity when the creator sets the surcharge to 0%. The extraction schema also lacks a way to carry unmapped obligations such as whitelisting or extended usage restrictions. [Offer schema and policy](../backend/app/domain.py#L21) · [Reply renderer](../backend/app/negotiation.py#L125) | Every material supported term appears in a commercial confirmation or is explicitly sent for clarification. Keep a typed record of unsupported or ambiguous obligations and add tests for zero-fee terms and mixed supported/unsupported deliverables. |
| P1 | **Commercial email needs an explicit retention boundary.** The live extraction request includes the current email body and earlier terms. LangGraph checkpoints include the email and commercial policy. The installed OpenAI adapter's generated Luna request omits an explicit `store` setting. Default Responses API storage and project-level controls differ from the app's seven-day cleanup. Actual account settings were outside this audit. [Provider input](../backend/app/models.py#L130) · [Checkpoint input](../backend/app/workflow.py#L176) · [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) | Verify provider settings and any required retention agreements, choose explicit request storage behavior, minimize model input and checkpoints, and test deletion across operational copies and backups. |
| P1 | **A thread can get stuck behind failed predecessor turns.** I reproduced the graph's hard stop with five earlier unresolved messages. New turns inherit the same unresolved queue. The UI retries the current failed revision, while storage exposes no recovery command for the older failed revisions that triggered the limit. [Extraction limit](../backend/app/workflow.py#L49) · [Retry transition](../backend/app/storage.py#L293) · [Prior context query](../backend/app/storage.py#L360) | An operator or creator can retry or explicitly mark a predecessor as skipped. A regression drives multiple failed sequential events and proves that the thread resumes without discarding accepted terms. |
| P1 | **A healthy API does not establish worker health.** API readiness checks database schema. The only worker polls analysis, delivery and the entire evaluation suite in the same execution lane. There is no heartbeat, persisted build/model identity for analysis jobs, queue-age threshold or tested restore. A long evaluation or failed worker can leave the UI available while negotiation work waits. [Readiness](../backend/app/api.py#L150) · [Worker job dispatch](../backend/app/worker.py#L24) · [Evaluation execution](../backend/app/evaluations.py#L57) | Verify worker heartbeat, time in queue and terminal failures through telemetry and alerts. Run evaluation work separately. Test a mixed-version rollout, process loss and database restore. Agree who owns alerts and the response. |

## Engineering improvements

| Area | Current state | Improvement |
| --- | --- | --- |
| Architecture and patterns | The API, worker, provider adapters, domain rules and UI are visibly separate. The transactional outbox, version-bound approvals, integer-cents pricing and database idempotency are appropriate. A single `Store` owns migrations, sessions, commands, read models, rendering, delivery and leases. The worker imports evaluation cleanup from the benchmark module. [Store](../backend/app/storage.py#L67) · [Worker cleanup](../backend/app/worker.py#L105) | Keep the current deployment shape. Organize by capability where responsibilities already differ: negotiation policy and copy, outbox and persistence, evaluation runner and fixtures, and shared operational configuration. Extract focused repositories or command services around existing transaction boundaries. Keep SQL and the locking invariants together. |
| API and frontend contracts | FastAPI validates write inputs. Frontend request handling casts unchecked response JSON to a generic type, discards the HTTP status, and follows a successful mutation with a read in the same error boundary. A create can commit and still leave the form open for a duplicate. Evaluation resume loses its run ID after a temporary read error. [API client](../frontend/lib.ts#L28) · [Workspace mutations](../frontend/app/page.tsx#L74) · [Evaluation polling](../frontend/app/evaluations/page.tsx#L45) | Add versioned and validated response schemas, discriminated errors and idempotency for creation and approval retries. Report the write outcome before refreshing reads. Keep run and draft state on transient failures, and recover from expired sessions. |
| Runtime efficiency | Each open workspace asks for the full thread snapshot every 900 ms, even while idle. The API rechecks the session and reads the thread and four collections. An idle tab can issue about 4,000 requests per hour at that interval. The thread also filters each collection for each revision as it renders. [Polling](../frontend/app/page.tsx#L50) · [Snapshot reads](../backend/app/storage.py#L336) · [Thread rendering](../frontend/components/negotiation-thread.tsx#L117) | Pause when hidden and back off when idle. Use a timeline cursor or conditional requests plus history pagination. Keep snapshots stable when unchanged and group thread rows once. Measure request counts, bytes, queue wait and database connections under representative concurrent sessions before selecting a larger stack. |
| AI and retrieval efficiency | Retrieval uses a bounded, versioned local document catalog with a read-only tool and checkpointed evidence. It fits the synthetic document workflow. The live model is called once for extraction and again to select two presentation values. Replaying unresolved history can add multiple calls. The eval's draft-quality rubric mainly tests observable structure and checked phrases. [Retrieval](../backend/app/retrieval.py#L12) · [Provider presentation](../backend/app/models.py#L155) · [Quality checks](../backend/app/evaluations.py#L248) | Make presentation local by default or keep the second call only if blind review measures a lift. Track call counts and end-to-end live latency. Add held-out, hands-on live reviews for ambiguous bundles, multilingual inputs, difficult counterparties, quote continuity and unsupported terms. Keep prompt, model and fixture versions with the evidence. Use a permissioned document corpus before expanding retrieval beyond the catalog. |
| Design system and accessibility | The UI has consistent visual vocabulary, palette variables, labeled controls and visible keyboard focus. Global styles and repeated class combinations carry most component rules. On narrow screens the thread moves ahead visually while DOM order remains unchanged. Hard policy rejections use the same green check icon as successful checks. [Responsive order](../frontend/app/globals.css#L169) · [DOM order](../frontend/app/page.tsx#L110) · [Policy checks UI](../frontend/components/agent-inspector.tsx#L38) | Establish reusable Button, Field, Alert, Status and Panel primitives. Define semantic tokens for typography, spacing, color and focus. Drive status from typed outcomes and use text plus icons. Align keyboard and visual order and verify contrast, keyboard operation, focus recovery, and screen reader announcements. [WCAG 2.2 focus guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) |
| Packaging, CI and ownership | Locked dependencies, a Dockerfile, a Compose entry point, CI and platform configuration exist. CI runs Python and browser checks on host processes. The current checkout had no commits, no remote and no independently verifiable hosted release. A new maintainer has no tagged baseline or deployment history. [CI](../.github/workflows/ci.yml#L28) · [Railway settings](../.railway/railway.ts#L3) | Produce a reviewed Git baseline and restore it in a clean checkout. Add lint/format, container and staging checks, Python dependency scanning and migration compatibility tests to CI. Record release ownership, environment setup, backup and rollback with tested commands. |

## Handoff sequence

1. **Fix commercial correctness and loss of work.** Close the stale-policy write, zero-fee scope omission, unsupported-term handling and failed-thread recovery. Add regressions for each.
2. **Decide the operating scope.** A synthetic demo can use controlled access and simulated email. Real creator workflows require account roles, provider-bound approval and explicit data handling before test users supply real email.
3. **Prove failure behavior and measurable performance.** Separate evaluations, add health and queue signals, exercise a rollback and restore, and baseline polling/network load and actual model quality.
4. **Package the handoff.** Publish the approved Git baseline through the team's normal process, verify a clean deployment and walk an independent operator through normal use, a failure and a rollback.

## Verification and limits

- Fresh local PostgreSQL run: **45 backend tests passed**. Ruff lint and formatting checks passed.
- The production Next.js build completed in a temporary copy. All four Chromium tests passed against a separate scripted database. The independent reviewer also verified TypeScript.
- The backend container built locally and its worker entry point started with `--help`. Docker Compose configuration passed validation.
- The recorded v3 evaluation artifact contains **28/28 scripted scenarios**. This audit used synthetic data and made no billable model calls.
- The production npm dependency audit reported zero advisories returned by its registry at the time of review. Python advisory scanning, cloud account settings, identity provider controls, live negotiation quality, and real delivery remain unverified.

## Remediation status

The findings above describe the original audit baseline. The working implementation now includes the following changes and local evidence.

| Area | Implemented and checked locally |
| --- | --- |
| Commercial correctness | Zero-fee exclusivity and delivery windows remain visible in the reply. Typed unmapped obligations require clarification, including when a newer message only changes the budget. |
| Policy edits | A form submits the policy version it originally opened. Conflict recovery is explicit and preserves unsaved edits. |
| Failed predecessors | The creator can retry or skip individual failed turns. A later turn can resume from accepted terms after the predecessor is resolved. The browser submits the current thread revision for older turns. Skipping a turn cancels unfinished reanalysis of the same message. Retry and skip actions are visible in the timeline. |
| Identity and delivery | The signed gateway and relay contracts bind authenticated creator membership, provider event IDs, the exact recipient, subject, sender, body, and approving actor. Local tests cover signed envelope preservation after reanalysis, recipient changes, and accepted receipts arriving after the worker exhausts retries. |
| Privacy and model efficiency | New checkpoints avoid duplicating raw email and the full policy. OpenAI requests explicitly set `store=False`; the live path uses one extraction call on a normal turn. Demo retention removes the thread checkpoints and synthetic tenant records together. |
| Worker health and packaging | Separate negotiation and evaluation lanes, renewable leases, worker heartbeats and authenticated queue status are implemented. The Docker release drill validates upgrade compatibility with the prior image, worker loss and recovery, and reading restored PostgreSQL data. |
| API, UI and accessibility | Typed responses and frontend runtime checks, ETags, timeline pagination, hidden-tab pause and idle backoff are in place. Semantic feedback, shared UI controls, focus recovery and mobile order have browser coverage. |
| Handoff and quality | The package includes an [operations runbook](operations.md), a [real-mail integration guide](real-mail-integration.md), and [held-out live negotiation review cases](live-negotiation-review.md). Local dependency scans and the production build passed. |

Production activation still requires a configured and tested identity gateway that supplies verified identity and workspace headers to browser API requests, a real mail relay, provider-account data controls and deletion policy, a hosted staging rollout with managed-backup restoration and alerts, and a held-out live negotiation quality review. The synthetic local checks use no provider credentials and send no real email.
